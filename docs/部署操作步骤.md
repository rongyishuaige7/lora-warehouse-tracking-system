# 仓库追踪系统：可信局域网部署步骤

本指南用于教学原型的手动真机复测。硬件身份、电源和接线尚未由当前公开提交验证，开始前先读 [`HARDWARE.md`](../HARDWARE.md) 与 [`VERIFICATION.md`](VERIFICATION.md)。

> **安全提醒：** Flask、网关控制 HTTP 和 LoRa 消息都没有认证或加密。只在隔离、可信的 2.4 GHz 局域网内测试，不要端口转发或暴露公网。真实 Wi-Fi 密码、IP 清单、设备 ID 和位置记录不要进入 Git、截图或 Issue。

## 0. 记录测试身份

开始前记录：

```bash
git rev-parse HEAD
```


## 1. 本地全量构建

```bash
bash scripts/verify.sh
```

这只证明源码可构建，不烧录硬件。

## 2. 启动 Flask

```bash
cd server
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
cp config.example.json config.json
python server.py
```

自检：

```bash
curl http://127.0.0.1:5000/api/health
```

`status=ok` 只说明 Flask 进程和配置可响应，不说明网关/标签在线。

## 3. 配置和烧录网关

从模板创建本地配置：

```bash
cp esp32_gateway/config.example.h esp32_gateway/config.h
```

编辑：

```c
#define WIFI_SSID "你的可信实验 Wi-Fi"
#define WIFI_PASSWORD "你的本地密码"
#define SERVER_URL_BASE "http://<Flask电脑的局域网IP>:5000"
#define SERVER_URL (SERVER_URL_BASE "/api/report")
#define GATEWAY_ID "GW001"
#define GATEWAY_REGION "A"
```

用 PlatformIO：

```bash
pio run -e gateway -t upload
pio device monitor -b 115200
```

或用 Arduino IDE 打开 `esp32_gateway/esp32_gateway.ino`。板型和端口必须按实物选择，不要机械照抄 `esp32dev`。

串口应至少出现 Wi-Fi 地址、`GET /api/health: 200`、`LoRa init OK! 433MHz` 和 HTTP server 启动信息。记下网关局域网地址，但不要公开。

## 4. 配置 Flask 到网关的下发地址

编辑本地 `server/config.json`：

```json
{
  "db_path": "warehouse.db",
  "gateway_ips": {
    "A": "http://<A区网关局域网IP>",
    "B": "http://<B区网关局域网IP>"
  }
}
```

没有 B 网关时可删除 B。重启 Flask。默认仓库代码不内置任何真实或历史局域网地址。

## 5. 配置和烧录标签

```bash
cp esp32_tag/config.example.h esp32_tag/config.h
```

编辑唯一 ID：

```c
#define DEVICE_ID "TAG001"
#define DEVICE_REGION "A"
```

标签 `DEVICE_REGION` 只是提示；服务端以实际接收网关区域为权威。标签默认不使用 Wi-Fi。

```bash
pio run -e tag -t upload
pio device monitor -b 115200
```

确认串口报告 JSON。当前电池字段应为 `null`；DHT 失败时温湿度也是 `null`，不能把它们写成真实 0 或 3.7 V。

## 6. 验证上报闭环

```bash
curl http://127.0.0.1:5000/api/devices
curl http://127.0.0.1:5000/api/regions
curl http://127.0.0.1:5000/api/history/TAG001?limit=10
```

预期设备记录包含接收网关的 `region`、`gateway_id`、RSSI 与服务器接收时间。至少再验证一次：让标签提示区域与网关区域不同，服务端仍应记录网关区域。

## 7. 构建和连接 Android App

```bash
cd android_app
ANDROID_HOME="$HOME/Android/Sdk" ./gradlew --no-daemon testDebugUnitTest assembleDebug
```

在真机安装 Debug APK 后，进入“服务器”设置，填写：

```text
http://<Flask电脑的可信局域网IP>:5000/
```

App 不接受公网明文 HTTP。真机不能使用 `127.0.0.1`（那是手机自己）；`10.0.2.2` 仅用于 Android 模拟器访问宿主机。

验证列表、搜索、A/B 计数和刷新来自同一轮真实上报。

## 8. 验证查找但不夸大结果

标签每次唤醒后约保持 10 秒清醒，默认每 30 秒心跳唤醒一次。

- 清醒窗口内点击“定位”：分别确认 Flask 返回、网关收到 HTTP、LoRa 发包、标签串口收到、JQ6500 实际播音；
- 深睡时点击“定位”：应只看到“已下发到网关但未确认标签收到或播放”的诚实提示；
- `QUERY` 只能让**已经清醒**的标签立即上报，不能通过 LoRa 唤醒深睡标签；
- 当前没有标签 ACK，网关 HTTP 200 不能替代播放证据。

## 9. 完成记录

逐项填写 [`VERIFICATION.md`](VERIFICATION.md) 的复测清单，保存脱敏串口日志、App 截图、标签/网关实物照片和 20–60 秒端到端视频。不得包含 Wi-Fi 密码、私网资产清单或个人路径。

## 常见问题

### 网关 `GET /api/health: -1`

检查 `SERVER_URL_BASE` 是否是 Flask 电脑地址、Flask 是否监听 `0.0.0.0:5000`、设备是否在同一可信网络以及防火墙是否允许实验流量。

### 标签发包但服务端没有数据

先看网关是否出现 `LoRa received`，再看 `HTTP Response: 200`。核对两端频率、Sync Word、SPI/DIO0 引脚、天线和供电；不要在未接匹配天线时持续发射。

### App 连接失败

真机填写 Flask 电脑的私网地址；模拟器可用默认 `10.0.2.2:5000`。公网主机必须使用 HTTPS。

### 点击定位没有声音

依次核对服务端是否配置了该区域网关、网关 `/control` 是否返回 200、标签是否正处于清醒窗口、LoRa 是否收到、JQ6500 是否有合法音频文件、扬声器/电源是否正确。深睡标签不会被 QUERY 或 PLAY_VOICE 唤醒。
